4.2.5.3 Integrasi Firebase dengan Backend Machine Learning

Integrasi antara Firebase Realtime Database dengan Backend Machine Learning (ML) merupakan jembatan utama dalam aliran data sistem deteksi drone ini. Proses ini melibatkan siklus berkelanjutan mulai dari akuisisi data mentah, prapemrosesan, hingga eksekusi model inferensi.

A. Aliran Data Real-time (Active Polling)
Backend ML (Node.js) melakukan sinkronisasi dengan Firebase melalui metode 'Active Polling'. Sistem melakukan pengecekan ke database setiap 2000 milidetik (2 detik) untuk memastikan data yang dianalisis adalah data terbaru dari sensor.

```javascript
// Loop Utama Polling & Trigger Inferensi
setInterval(async () => {
    const snapshot = await get(ref(db, 'detection_system'));
    const nodes = snapshot.val();
    
    for (const [nodeKey, nodeData] of Object.entries(nodes)) {
        let hex = String(nodeData.data_hex || "");
        
        // Membandingkan data saat ini dengan data sebelumnya di memori
        if (lastHexMap[nodeKey] !== hex) {
            lastHexMap[nodeKey] = hex; // Update data terakhir

            // TRIGGER: Memanggil fungsi Inferensi ML
            const prediction = await performInference(hex);
            
            // Broadcast hasil ke Dashboard (Lihat Bagian 4.2.5.4)
            broadcastToDashboard(nodeKey, prediction, nodeData);
        }
    }
}, 2000);
```

B. Pemanggilan Model ML (ONNX Engine)
Setelah data mentah (Hex) berhasil ditarik, Backend ML memanggil fungsi 'performInference'. Di dalam fungsi ini, terjadi proses "Bridge" antara data mentah dengan model AI (ONNX). Proses ini terdiri dari tiga tahap:

1. Konversi Data (Preprocessing):
Data heksadesimal dari sensor dikonversi menjadi array integer. Karena model ML membutuhkan input sebanyak 63 fitur, dilakukan proses "Padding" (menambah angka 0) jika data kurang, atau "Trimming" jika data berlebih.

2. Pembuatan Tensor:
Data yang telah dibersihkan kemudian dibungkus ke dalam objek 'Tensor' dengan tipe data Float32, sesuai dengan kontrak input pada model drone_detector_model.onnx.

3. Eksekusi Inferensi:
Fungsi `ortSession.run()` dipanggil untuk mengeksekusi model. Hasil keluaran berupa probabilitas label yang kemudian dipetakan ke dalam status ancaman manusiawi (WIFI, WIFI+BT, atau DRONE).

```javascript
async function performInference(hexStr) {
    // 1. Preprocessing (Hex to Integer)
    let newData = convertHexToArr(hexStr);
    
    // 2. Pembuatan Tensor (Float32, 1x63 features)
    const tensor = new ort.Tensor('float32', new Float32Array(newData), [1, 63]);

    // 3. Eksekusi Model
    const results = await ortSession.run({ float_input: tensor }, ['output_label']);
    
    // Output Mapping
    return mapping[results.output_label.data[0]];
}
```

C. Analisis Efisiensi Integrasi
Mekanisme integrasi ini sangat efisien karena:
- Database Firebase tidak dibebani dengan proses tulis (write) hasil ML, melainkan hanya baca (read) data mentah.
- Inferensi hanya terjadi jika ada data baru yang masuk (efisiensi CPU).
- Koneksi Socket.io memastikan hasil ML sampai ke user dalam milidetik.
